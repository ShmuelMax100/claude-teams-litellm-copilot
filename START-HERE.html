Deploy, verify, then invite

  1. Build the pinned Fusion image and review the Terraform examples in infra/terraform.
  2. Store a distinct GitHub fine-grained PAT for each user in Key Vault, with Copilot Requests permission and the real expiry.
  3. Deploy both applications in one ACA environment, with Fusion private and only LiteLLM public. Follow docs/AZURE-DEPLOYMENT.md.
  4. Create the matching LiteLLM user ID with role internal_user, administrator-managed metadata.github_login, and automatic key generation disabled. The exact management API body is in docs/ADMINISTRATOR.md. Verify the deployed configuration.

Administrator: verify the deployed gateway

./setup admin prepare --gateway https://gateway.example --upstream https://fusion.internal.example/v1

Administrator: issue a personal invitation

./setup admin enroll --gateway https://gateway.example --upstream https://fusion.internal.example/v1 --user-id developer-id --github-login developer-login --tier standard --out private/developer.invite.json --apply

The invitation contains a personal gateway key. Transfer it privately. Never include GitHub credentials. Read docs/ADMINISTRATOR.md before provisioning.

Connect your Claude Code

Use your administrator's personal invitation. Join verifies it and backs up your settings before writing the gateway configuration. GitHub credentials remain on the server.

Developer: connect Claude Code

Model requests and tools have different interfaces

Claude Code sends Anthropic Messages to LiteLLM. The gateway authenticates the personal key, translates the request to Chat Completions and signs the user's identity. Fusion resolves that user's server-side credential and creates an isolated SDK session.

Text streams back while Fusion runs. Complete validated tool calls return to Claude Code for local execution. MCP is a separate private tool endpoint; it is not the model adapter and is not registered with a shared user token.

All three model names—fusion-standard, fusion-high and fusion-max—use this same route. The key grants its selected tier.

Know the compatibility boundary

Anthropic does not support routing Claude Code to non-Claude models. This adapter implements a tested text-and-tools subset, not full Claude feature compatibility.

The stable SDK accepts prior conversation as serialized context, not lossless native Claude history. Images, audio, advanced thinking, forced tool selection and unsupported options fail explicitly. The returned-output byte cap does not limit upstream generation charges.

Warm containers reduce startup delay. Network and model generation still add latency. A failure never switches provider; restarting a request may repeat work.

Check the deployment in layers

Setup and doctor check authorization and configuration without model inference. Automated tests cover request translation, streaming, tool calls, two-user isolation, service failures, expired credentials and the absence of alternative routing.

Native offline SDK probes verify runtime and tool interfaces. They do not establish live account entitlement. A real Fusion request requires the user's own approved credential. Read docs/VALIDATION.md and docs/IMPLEMENTATION-RESULTS.md for current evidence.
